# Working agreements

- After finishing a requested change, report that it's done — do not explain what you did unless asked. Then ask, in no more than 3-4 lines, whether the user wants an explanation and, if so, of which part.
- Any new commit or merge on `testing` must be pushed immediately and followed by the `deploy-testing` skill (`.claude/skills/deploy-testing/SKILL.md`).
- Antes de trabajar en una feature nueva o existente, revisa `docs/funcionalidades.md` para saber su estado (disponible, limitada, por pulir o planeada). Al terminar, actualiza ese documento si la feature cambió de estado, se agregó o se quitó, y actualiza la fecha de revisión.
